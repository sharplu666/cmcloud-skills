# AI生图（文生图 + 图生图 · 统一图像处理入口）

## 概述

本技能是**所有 AI 生图/图片处理的统一入口**，同一接口支持两种模式：

- **文生图**：无输入图，只传 `query`（文本描述）即可生成全新图片；
- **图生图**：传入至少一张输入图（云盘图片），基于已有图片做 AI 生成/编辑。用户上传、搜索、筛选或前序步骤获得的图片，凡需要 AI 生成/编辑新图片的，都由本技能承接。原「云盘图像处理工具集」中的固定场景能力（AI头像、AI扩图、智能美颜、宝宝长相预测、宝宝时光机、智能抠图、AI漫画风、画质修复、图像矫正、老照片修复）已并入本技能，统一改写为图生图任务执行，由后端完成意图识别、场景提示词匹配与模型调用。

> 注意：生图为长耗时任务，默认约 120 秒内未完成会返回 `taskId`，用户可凭 `taskId` 主动轮询取结果（见[执行流程 ⑥](#执行流程)）。

## 能力边界

### 承接范围

| 场景类别 | 示例 |
|---------|------|
| 文生图（无输入图） | "帮我画一只在太空吃披萨的猫"、"生成一张日落海滩图" |
| 自然语言改图 | 背景消除/替换、去掉路人、元素增删、换天空、图片合成（人像+背景） |
| 风格转换 | 转动漫/漫画风、电影海报风、黑白电影感 |
| AI头像 | 人物照片转卡通/写实/二次元头像 |
| AI扩图 | 向外扩展画面、延伸背景、改成 16:9 |
| 智能美颜 | 人像磨皮、美白、风格化美颜 |
| 宝宝长相预测 / 宝宝时光机 | 父母照片预测宝宝样貌、预测成长变化 |
| 智能抠图 | 识别人物主体、透明背景 |
| 画质修复 | 提升清晰度、2/4/8 倍放大、老照片修复 |
| 图像矫正 | 铺平、扭曲矫正、文档矫正 |
| 批量处理 | 多张图做同一处理（超 14 张自动分批） |
| 多轮追加编辑 | "再把上一张图改成动漫风" |

### 特殊路径（纳入意图识别，但不走生图执行）

| 场景 | 处理路径 |
|------|---------|
| 图片配文（图片进、**文字**出） | 生图接口无法产出文字；识别该意图后向用户说明，并引导使用具备图片理解对话能力的入口 |
| 图片编辑保存（裁剪/旋转/翻转后存云盘） | 纯工具操作不经 AI 模型；转交本工具集「图片编辑保存」子能力（`../image_edit_save/index.md`） |

### 不承接

- **仅搜索/整理图片**（无创作意图）→ 转交「云盘文件管理」；
- 与图片生成、编辑无关的其他任务。

## 参数说明

### 必选参数
| 参数 | 类型 | 说明 |
|------|------|------|
| query | String | 创作/编辑提示词（经 Step 0 改写，只含图片创作内容）。文生图时即为完整的画面描述。**未指定保存路径时，结果自动保存到默认文件夹**（「对话文件」下按会话生成的目录，如会话首条消息为「生成璀璨星空图」→ `/AI空间/MClaw空间/对话文件/生成璀璨星空图`） |

> 用户未指定**保存路径**时，结果自动保存到**默认文件夹**（「对话文件」下按会话生成的目录），无需用户或模型干预。

### 可选参数
| 参数 | 类型 | 说明 |
|------|------|------|
| 输入图（`fileId`） | — | 图生图时提供至少一张输入图；**不传即为文生图**，详见下方「输入图」 |
| size | String | 生成尺寸，如 `2048x2048`；宽高比 `[1/16, 16]`、总像素约 `2560x1440 ~ 3072x3072`；非 `WxH`（如 `2K`/`3K`）直接透传 |
| seed | Int | 随机种子，取值 `[-1, 2147483647]`，默认不传 |
| sequentialImageGeneration | String | 组图模式：`auto`（自动判断组图）/ `disabled`（单张） |
| sequentialMaxImages | Int | 组图最大张数 `[1, 15]`（仅 `auto` 生效），且「输入图数 + 生成数 ≤ 15」；**组图模式不支持分批** |
| optimizePromptModel | String | 提示词优化模型：`standard` / `fast` |
| saveDirId | String | 向用户询问**保存路径**（或用默认文件夹），由「云盘文件管理」技能把路径解析为 fileId 后传入；**不要直接向用户要 fileId**。脚本据此把结果直接移动到该目录并输出去查看回执。用户未指定路径时省略 |

### 输入图（可选）

传入输入图即为**图生图**；**不传输入图即为文生图**（仅凭 query 生成）。

> 输入图约束（接口文档）：**单批最多 14 张**、**每张 ≤ 10MB**、**单张像素 ≤ 6000×6000**；单张超限脚本会报错（fileId 的 size/宽高取不到时该项跳过）。**超过 14 张时脚本自动分批**（见[执行流程 ⑤](#执行流程)），无需用户拆分。

| 参数 | 对应 sendType | 说明 |
|------|---------------|------|
| `fileId`（可多个） | 3 | 云盘文件 ID（唯一支持来源）。由前置搜索/整理/上下文得到；脚本用 batchGet 校验存在性与大小/像素。本地图片需先经「云盘文件管理」技能上传到云盘后以 `fileId` 传入 |

## 执行流程

### 0. 创作指令提取（query 改写）

从用户原始需求中提取**只包含图片创作/编辑内容**的语句作为 query：

- 删除搜索、筛选、整理、归档等非创作指令（这些由前置技能完成，不进 query）；
- 结合上下文补全指代（"这张图"、"这些图片"、"上一张图"）；
- 不增加用户未提出的创作需求；多动作需求完整保留（"去掉路人并把天空换成晚霞"）；
- 文生图时保留用户的完整画面描述，可适当补全为具体、可画的描述（主体/场景/风格），但不添加用户未提出的内容；
- 命中固定场景（头像/抠图/美颜等）时，query 保留用户原意即可，场景匹配由后端完成，**不要**自行编造专业提示词；
- **多图人物合成指令**（把一张图的人放到/移到/P到/合到另一张图中）：先判定指令中是否出现明确语义关键词——
  - 出现"替换/换成"→ query 用替换语义；出现"合照/合影/同框/合在一起/放在一起/一起"→ query 用合照语义。**只要出现其中任一关键词，无论句中其他措辞如何（即使同时出现"P到…里"等模糊动词），都视为语义明确，禁止再追问**；
  - 以上关键词均未出现 → 必须按「执行流程 4 · 多图人物合成意图澄清」先做二选一澄清，**澄清前不得生成 query、不得进入二次确认**。
- **图生图剥离输入图张数限定词**：用户表述中用于**指代输入图数量**的词（"这两张/三张/N张图片"）**不写进 query**，统一改为不带数量的指代（"把图片改成动漫风格"、"把这些图片都转成黑白风格"）。输入图张数由随请求提交的输入图列表表达，无需也不应由 query 文本声明，避免后端把指代数量误读为**生成张数**。与下方「张数追加」不冲突：追加的是**生成张数**（文生图与风格转换场景），此处剥离的是**输入图指代数量**。
- **文生图与风格转换的张数追加**：这两类场景的 query **末尾**必须显式追加生成张数，固定格式为 `。预期生成图片总数：{X}`（query 原文末尾无句号时先补「。」再追加；追加内容末尾**不加**句号）。**禁止**在 query 开头或正文中用"一张/几张/N张"等描述语句表达生成张数。后端按 query 文本判断生成张数，接口张数参数不生效；不追加时后端默认生成两张，与用户默认预期矛盾——
  - **文生图**：用户未提张数 → X=1（如 `一只在太空吃披萨的猫。预期生成图片总数：1`）；用户指定张数（如"十张"）→ X=指定值，且张数词不进 query 正文（如 `不同姿势的猫。预期生成图片总数：10`）；
  - **风格转换**：用户未提张数 → X=输入图张数，即生成数量与上传数量保持一致（单图：`把这张图片改成动漫风格。预期生成图片总数：1`；多张图同一风格转换：`把图片改成动漫风格。预期生成图片总数：2`）；用户明确指定生成张数时，以用户指定为准；
  - 仅限文生图与风格转换场景（含多张图同一风格转换）；非风格转换的批量处理（如批量去背景/抠图）、组图、多图人物合成等场景**不追加**，保持现有行为；风格转换输入图**超 14 张触发自动分批时也不追加**（脚本同一 query 逐批提交，追加总数会被每个批次误用）。

**改写示例**：

| 用户原始需求 | query（创作指令） |
|-------------|------------------|
| 帮我画一只在太空吃披萨的猫 | 一只在太空吃披萨的猫。预期生成图片总数：1 |
| 帮我画十张不同姿势的猫 | 不同姿势的猫。预期生成图片总数：10 |
| 帮找我和儿子的合照，每年选2张，把后面的背景P掉 | 把后面的背景P掉 |
| 从旅行照里选3张做成电影海报风格 | 做成电影海报风格。预期生成图片总数：3 |
| 找一张我在海边的照片，把路人去掉，天空换成晚霞，再扩成16:9 | 把路人去掉，天空换成晚霞，再扩成16:9 |
| 把上一张图改成动漫风 | 把这张图片改成动漫风格。预期生成图片总数：1 |
| 把这两张图片动漫化（两张输入图同一风格转换） | 把图片改成动漫风格。预期生成图片总数：2 |
| 把这几张照片都转成黑白 | 把这些图片都转成黑白风格。预期生成图片总数：N（N=实际上传图数） |
| 将第一张图的人物放到第二张图中（澄清后用户选择：替换） | 将第一张图的人物替换掉第二张图中的人物，保留第二张图的背景与风格 |
| 将第一张图的人物放到第二张图中（澄清后用户选择：合照） | 将第一张图的人物融入第二张图，与其中的人物自然同框合影 |
| 把第一张图的人P到第二张里，做成我们的合照（含"合照"，语义明确，无需追问） | 将第一张图的人物融入第二张图，与其中的人物自然同框合影 |
| 把第一张的人和第二张的人合在一起（"合在一起"=两人都在，语义明确，无需追问） | 将第一张图的人物融入第二张图，与其中的人物自然同框合影 |

### 1. 模式判定与前置图片获取

**先判定模式**：

- **文生图**：用户只想凭文字描述生成全新图片，未提供也未指向任何已有图片 → 无需前置取图，直接进入「保存路径确认」；
- **图生图**：用户提供了图片，或要"改图/把图里的…p掉/合成"等基于已有图编辑，或承接前序搜索/整理结果的图片 → 按下表获取输入图。

**前置图片获取（图生图、上下文无图时）**：

| 场景 | 路由目标 | 说明 |
|------|---------|------|
| 用户已提供图片 / 上下文有 fileId | 无需前置 | 直接使用上下文中的 fileIds |
| 上下文仅有相册（`:::albumList`，只有 albumId） | 见下方「指代解析」 | 回溯同会话前序预览卡 `:::imageList` 提取 fileIds |
| 仅需要找图（"找一张我在海边的照片"） | 「云盘文件管理」 | 使用其 `search_image` 语义搜图 |
| 需要搜索 + 筛选/整理（"每年选2张"、"整理成册后处理"） | 「云盘文件管理」 | 使用其照片整理/选图能力 |

**多轮对话指代解析**：用户说"这张图/这个图片/这些图片/上一张图"时，从对话上下文定位前序技能输出：
1. 前序输出是图片列表（`:::imageList`，含 fileId）→ 直接提取使用；
2. 前序最终输出是相册卡片（`:::albumList`，仅 albumId）→ **回溯同一会话中整理/搜索流程预览阶段的 `:::imageList` 卡片提取 fileIds**；
3. 上下文中的 fileIds 不完整（预览卡分页 `loadMore=true` 只含首页、或交接快速路径跳过了预览）→ 转交「云盘文件管理」的 `search_image`，按用户指定范围语义搜图重新定位（如"6月我和儿子的合照"）；
4. **禁止凭空猜测 fileId**；注意：「云盘文件管理」无"按 albumId 列相册内容"能力，不得尝试。

**禁止在本技能内实现搜图/整理逻辑**；前置技能返回图片后须向用户展示并确认「这些图片是否符合预期」，用户不满意则返回前置技能重新搜索/整理，禁止自行决策。

### 2. 保存路径确认（优先）

**先判断保存目标是不是知识库**：用户明确说"保存到知识库 / 存到知识库 / 导入知识库"时，**不走云盘路径解析、不传 `saveDirId`**，按以下链路处理：

1. 正常执行生图命令（与其他场景一致，不加任何特殊参数），脚本把结果归档到默认文件夹并输出回执卡；
2. 生成成功后，从结果大图卡（`:::bigImageList`）中提取结果 `fileId`，转交「知识库管理」技能的 `upload_cloud_file --cloud-file-id "<结果fileId>"` 完成知识库导入（该命令内部自动下载再上传，与文件在云盘哪个目录无关）；
3. 若生图超时返回了 `taskId`，用户后续用 `status.py` 查询拿到结果后，同样提取结果 `fileId` 转交「知识库管理」。

用户提到的是**云盘保存路径**（如"保存到XXX"、"存到XXX文件夹"）时，**必须**优先确认保存路径，再进行后续参数收集：

1. 调用中国移动「云盘文件管理」技能搜索目标文件夹 "<文件夹名>"
2. 判断保存路径是否合法（`filePath` 以 `/AI空间/MClaw空间` 开头）：
   - **合法路径唯一**：直接确认，继续后续步骤
   - **合法路径不唯一**：立即停止，列出所有合法路径供用户选择，**禁止自行决策**
   - **保存路径不存在**：**直接**由「云盘文件管理」技能创建 `/AI空间/MClaw空间/<用户指定路径>` 目录（**无需再询问用户**），创建后取其 `fileId` 作为 `saveDirId`
3. 确认合法目录后，取其 `fileId` 作为 `saveDirId` 传入脚本——脚本会据此把结果**直接移动到该目录**并输出去查看回执，**无需模型再单独调用云盘移动**
4. 如果用户未指定保存路径，跳过此步骤（结果自动保存到默认文件夹）

### 3. 参数收集

从用户上下文中提取参数：
- **提示词（query）**：经 Step 0 改写的创作指令
- **输入图（仅图生图）**：取云盘图片 `fileId`，多张空格分隔。图生图场景下未提供输入图时必须先向用户索取；**文生图场景直接省略**
- **生成参数**：根据用户偏好可选填 `size`、`sequentialImageGeneration`、`optimizePromptModel`；未提及则不传，使用接口默认

- **参数完整性检查**：收集完成后检查必选参数是否齐全（query 必填；图生图还需至少一张输入图）
  - 参数齐全：进入下一步「范围澄清与二次确认」
  - 参数不完整或有歧义：向用户追问缺失或模糊的信息（如query过于简短模糊、图生图缺少输入图）

### 4. 范围澄清与二次确认

**范围澄清（确认前必须处理）**：
- **多图人物合成意图澄清**：当用户指令涉及"把/将一张图的人物放/移/加/P/合到另一张图中"这类多图人物合成时，**先判断成品图的人物构成是否已在指令中明确**：
  - **已明确（禁止追问，直接按语义改写 query）**：只要指令中出现"替换/换成/合照/合影/同框/合在一起/放在一起/一起"任一关键词，**无论句中其他措辞如何**都视为语义明确：
    - "替换/换成"→ 替换语义："将第一张图的人物替换掉第二张图中的人物，保留第二张图的背景与风格"；
    - "合照/合影/同框/合在一起/放在一起/一起"→ 合照语义："将第一张图的人物融入第二张图，与其中的人物自然同框合影"；
  - **不明确（必须二选一追问，禁止自行猜测、禁止直接进二次确认）**：指令仅说"放到/移到/放进/P到/加到第二张图中"等，未说明成品图里只有第一张的人还是两人都在时，向用户确认：
    - **A. 替换**：用第一张图的人物替换掉第二张图中的人物（成品里只有第一张图的人）；
    - **B. 合照**：把第一张图的人物自然融入第二张图，与图中原有人物同框（成品里两人都在）。
    确认后按用户选择将语义写死进 query（写法同上述两种）；
- 指代数量与用户表述不一致时（如用户说"这个图片"但上下文是 24 张的相册），必须询问用户具体处理哪几张，禁止自行猜测；
- 待处理图片**超过 14 张**时，告知用户"共 N 张，将自动分批处理（每批最多 14 张）"，确认后一次执行即可（脚本内自动分批，无需多次调用）；
- 注意区分：**批量处理**（每张图独立做同一处理 → 分批多任务）与**组图**（一次任务产出相关联的一组图 → `sequentialImageGeneration=auto`，输入图+生成数 ≤15）是两种模式，不要混淆。

**二次确认前置检查**：发起二次确认前，必须先检查当前请求是否为**多图人物合成指令**（把一张图的人放到/移到/P到/合到另一张图中）：若指令未含"替换/换成/合照/合影/同框/合在一起/放在一起/一起"任一明确关键词，且本次对话尚未做过「多图人物合成意图澄清」的二选一确认，**禁止直接发起二次确认**，必须先回到上方澄清流程向用户追问。反之，指令已含明确关键词的，**禁止再追问**，直接按对应语义发起二次确认。

**二次确认**：**先向用户确认再执行**（不要直接执行）。用**中文**复述抽取到的参数（描述/输入图/尺寸/保存路径），**不要出现 `query/fileId/size/sendType` 等接口词**，最后问一句"确认开始生成吗？"。

**输出格式要求（重要）**：每项参数必须**独占一行**，用 markdown 列表项（`- `）输出，**禁止**把参数连成一段或一行。模板：

好嘞，我按以下内容帮你生成——

- 描述：{描述}
- 输入图：{云盘图片 N 张 / 无（文生图）}{，超过 14 张将自动分批}
- 尺寸：{尺寸 或 默认}
- 保存路径：{用户指定路径（不存在时将自动新建）或 默认文件夹 或 知识库（同时归档到默认文件夹）}

确认开始生成吗？

用户回复"确认"后，才进入下一步执行；未确认不执行。

### 5. 执行

**先发送任务描述**：执行命令前，先向用户发送一句等待中提示语——**只描述客观事实**（处理指令/图片张数/输出尺寸），禁止编造完成时间或成功承诺。例如："正在为您处理 3 张图片：把背景人物去掉（输出尺寸默认），请稍候..."；文生图示例："正在为您生成图片：一只在太空吃披萨的猫（输出尺寸默认），请稍候..."

执行以下命令，**在命令结束前不要结束本轮回复**——提交后在同一轮内持续轮询（每约 5 秒一次）直到命令结束，每次可向用户简报一次进度；**禁止**用"我会持续关注/稍后告知你结果"这类话术结束本轮（轮次结束后不会再被唤醒来查询，该承诺无法兑现）：
```bash
python3 {baseDir}/ai_image_generate/scripts/main.py \
  --query "{query}" \
  --file-id "{输入图fileId1}" "{输入图fileId2}" \
  --size 2048x2048 \
  --save-dir-id "{saveDirId}" \
  --confirm
```

**保存到知识库时**（保存路径确认为"知识库"）：按上方普通命令执行即可（不传 `--save-dir-id`，结果归档到默认文件夹）；生成成功后从结果大图卡（`:::bigImageList`）提取结果 `fileId`，转交「知识库管理」技能 `upload_cloud_file --cloud-file-id "<结果fileId>"` 完成导入。
- **文生图**：省略 `--file-id`，只传 `--query` 即可
- 图生图输入图用 `--file-id` 传入云盘图片
- 用户未指定保存路径时省略 `--save-dir-id`（结果自动保存到默认文件夹）
- 保存路径为知识库时无需特殊参数：结果正常归档到默认目录，生成后提取结果 `fileId` 转交「知识库管理」（见「保存路径确认」）
- 输入图超过 14 张时直接全部传入：脚本自动分批（每批 ≤14 张、逐批提交、统一轮询、汇总为一组结果卡片），并打印各批次 `taskId`
- 过程中必须**每约 5 秒**给用户详细通报一次状态（在同一轮内反复轮询，见上）

### 6. 任务仍在生成中（用户轮询能力——仅用户主动询问时）

AI生图为长耗时任务。`main.py` 默认在约 120 秒内轮询，若仍未完成，会返回 `taskId`（分批时返回各批次 `taskId`）并告知用户，**不会自动继续轮询**。**仅当命令已结束并返回 `taskId` 后，才允许结束本轮回复**；命令仍在运行时不得结束本轮（见「执行流程 ⑤」）。

- **仅当用户主动询问进度/结果**时，才调用 `status.py` 查询：
```bash
python3 {baseDir}/ai_image_generate/scripts/status.py --task-id "{taskId}" --wait
# 分批任务：一次传多个 taskId，成功结果汇总为一组卡片
python3 {baseDir}/ai_image_generate/scripts/status.py --task-id "{taskId1}" "{taskId2}" --wait
```
  - `--wait`：有界内部轮询（最多约 480 秒）；不传则单次查询当前状态
  - `--save-dir-id`：可选；未传则归档到会话默认目录（与 main.py 一致）
- **如果用户没有主动询问进度/结果，不要主动展示或引导 `status.py`**；正常告知"任务还在生成中，需要时告诉我查询"即可

## 结果总结

脚本执行完成后，用**纯文字**做一句简短的任务完成确认即可（如"已经生成好啦～"），**不要输出** `:::bigImageList`、`:::filePathList`、`:::imageList` 等任何渲染卡——卡片由脚本/前端自动展示，模型不复述、不拼装 fileId、不引导用户点击"去查看"。

**格式约束**：
- **正文严禁出现保存路径**（如"已保存到 /AI空间/..."）、**严禁**出现"点击去查看""点下面卡片就能看到"等指引；卡片与路径入口均由前端自动展示
- **涉敏处理**：当 API 返回涉敏相关信息时，只转述 API 原文，禁止添加任何分析、猜测原因、替换建议或替代方案（如"可能是因为…"、"建议更换…"等均禁止）
- 其他无结果图等异常情况：根据脚本返回内容如实总结描述

### 保存路径说明

脚本已完成结果文件的移动（用户未指定保存路径时，移动到**默认文件夹**——「对话文件」下按会话生成的目录），模型**无需**再调用云盘移动，也**无需**在正文中复述保存路径或提示"去查看卡片"。

**保存到知识库场景**：结果先正常归档到云盘默认目录（与常规生图一致），模型再从结果大图卡（`:::bigImageList`）中提取结果 `fileId`，转交「知识库管理」技能的 `upload_cloud_file` 完成导入；知识库回执卡按该技能规则透传。

## 错误处理
- **图生图未提供输入图**：用户意图明显是"改图/基于某张图编辑"但拿不到输入图时，告知「需要你先上传或指定要处理的图片」，并询问具体处理哪张；用户只想凭文字生成新图时直接按文生图执行，无需索图
- **提示词过短或模糊**：如果用户描述太简短（如"改一下"、"画个图"），询问更具体的创作/编辑意图
- **输入图缺失/失效**：输入图 fileId 不存在或无法访问时脚本会报错，需提示用户重新提供
- **前置搜索/整理返回为空**：停止流程，告知用户未找到符合条件的图片
- **指代无法解析**：上下文中找不到用户所指的图片时，向用户询问具体要处理哪张，禁止猜测 fileId
- **分批部分失败**：脚本会汇总输出成功批次的结果并列出失败/未完成批次及 taskId，如实告知用户，询问是否重试失败批次
- **任务超时**：`main.py` 返回 `taskId` 时，告知用户"任务还在生成中，需要时告诉我用 status.py 查询"，由用户决定是否轮询
- **任务失败/过期**：脚本会抛出 `status=4/5` 的错误，如实告知用户并建议调整提示词或重试
- **纯搜索/整理任务误触发**：拒绝执行，引导至正确技能
