# 云盘文件管理

本技能是云盘文件/图片搜索、文件原子操作与整理到个人云目录/相册/回忆故事的入口。具体能力见分册，**执行任何命令前必须先读取对应分册文档，参数与示例以分册为准**。

能力分四类，先定性用户意图属于哪一类，再在类内挑命令：

- **搜索**的产物是结果集`<handle>`，**精选**、**过滤** 与 **整理** 都以它为输入；
- **精选**、**过滤** 的子集可再精选、再合并生成`<handle>`，或直接送去整理；
- **整理**是终点动作，提交后回执见 stdout（成功/已提交等待推送）。
- **文件原子操作**：修改指定 fileId 的文件

## 一、搜索能力

根据用户的query搜索文件：
- **语义搜图**（一句话自然语言找图：画面内容/地点/时间/事件/人物等任意维度）→ [SEARCH-FILE.md](./references/SEARCH-FILE.md)
- **文件/文件夹条件搜索**（含备份目录范围）  → [SEARCH-FILE.md](./references/SEARCH-FILE.md)
- **个人动态搜索** → [SEARCH-FILE.md](./references/SEARCH-FILE.md)
- **批量文件/文件夹 `<fileId>` 获取 `<handle>` 承接下游能力** → [SEARCH-FILE.md](./references/SEARCH-FILE.md)
- **转存搜索**（按转存来源查文件：分享转存 / 圈子转存 / 发现转存）→ [SEARCH-TRANSFER.md](./references/SEARCH-TRANSFER.md)
- **图文搜人**（参考图 + 描述找人物照片）→ [SEARCH-PERSON-IMAGE.md](./references/SEARCH-PERSON-IMAGE.md)

### 选路（图文搜人 vs 语义搜图）

二者本质不同：
- **语义搜图没有视觉锚点**——文字本身描述要找什么，靠语义匹配未知的图
- **图文搜人有人脸锚点**——参考图锁定一个已知的人，文字只用来圈定"是图里哪个人"，再按人脸在全库找这个人。

判据：要锁定的人，能不能被用户指出的参考图圈住？
- 能 → `图文搜人`；
- 不能、只能靠文字描述 → `语义搜图`

推论：
- 按照语义信息找人但没参考图 → `语义搜图`；语义搜图可按画面中的人物（我/亲属称谓/人名）检索，称谓原样传入，见 [SEARCH-FILE.md](./references/SEARCH-FILE.md)
- 按照语义信息找除了人以外的其他目标（如风景、物品等）→ `语义搜图`
- 参考图来源：本轮上传的图 / 指代某张已有图（含「换目标继续找」）/ 称呼绑定过身份的人物
- 锚点靠用户指出来，不自动携带未指代的历史图；判前扫一遍称呼，绑定过即使用 `图文搜人` 并按分册转写称呼

### 搜索结果

搜索能力输出的结果集用 `<handle>` 标记，是精选过滤与整理能力的前置输入。 

## 二、文件原子操作 → [OPERATIONS.md](./references/OPERATIONS.md)

一步一个动作，互不依赖，不产生可复用语料，不产生 `<handle>`，**不能承接精选/整理**。

- **上传文件**：上传到云盘指定目录
- **下载文件**：下载云盘文件到本地目录
- **分享转存**：把别人的 139 分享链接中的文件转存到自己云盘 → [SHARE-SAVE.md](./references/SHARE-SAVE.md)
- **分享转存并下载**：转存后一步下载到本地（保留分享内目录结构）→ [SHARE-SAVE.md](./references/SHARE-SAVE.md)

> **注意（2026-10-04 实测）**：`search` / `semantic-search` / `dynamic` / `person-search` / `search-by-ids` 所依赖的
> 139 AI 搜索接口（ai.yun.139.com）已下线（404），`search-transfer` 的转存查询接口（huidu-middle）不可达；
> 这些命令现会返回明确的降级提示与替代方案。文件原子操作（上传/下载/查详情/判存在/复制/移动/重命名/建目录）
> 与 `share-save` / `share-download` 不受影响。
- **批量移动/复制**：把一批文件移动/复制到云盘指定
- **创建目录**：按完整云盘路径创建目录（含中间各级）
- **重命名**：提供`<fileId>`，对一个或多个文件重命名
- **默认保存目录**：创建（创建或确保存在）/ 查询（只查不建）
- **按 ID 查详情**：按已知`<fileId>`查询文件元数据
- **播放视频/音频**：按已知`<fileId>`触发前端播放单条视频/音频
- **查询文件路径**：按已知`<fileId>`查询完整云盘路径
- **批量检查是否存在**：批量检查指定父目录下是否存在同名文件/文件夹

## 三、精选过滤（消费搜索结果） → [REFINE.md](./references/REFINE.md)

**前置依赖**：精选过滤必须以`<handle>`为输入，输出`<handle>`子集或`<handle>`合并语料，可再精选、再合并或送去整理。

- **照片精选/去重**：对照片搜索结果`<handle>`去重/精选
- **搜索结果合并**：合并多批搜索/精选/去重结果（同 fileId 只留首现）

## 四、整理类（终点动作） → [ORGANIZE.md](./references/ORGANIZE.md)

把搜索/精选/合并后的结果落位到个人云目录、相册或回忆故事。

**前置依赖**：整理必须以`<handle>`为输入，没有`<handle>`时先执行搜索能力。

- **整理方向推荐**：用户没说整理去向时，先出推荐（回忆故事/相册/个人云目录三情形并列）供用户选定
- **整理到个人云目录**：按照固定维度整理到个人云目录，支持规则化重命名
- **整理到相册/回忆故事**：按照固定维度整理到相册/回忆故事

## 不适用场景

- 知识库上传 → 知识库管理
- 删除云盘文件：本技能**不支持删除云盘文件**，收到删除诉求时如实告知用户无此能力

## 常见问题和安全限制

### 稳定性风险

- 用户对已有`<handle>`提出收窄或变换诉求（只要某日/某地/某类、换个维度重新分组等）:
  - **条件能通过对现有`<handle>`重新分组得到**，则复用`<handle>`并且通过重新指定分组维度来实现，**禁止重新发起搜索**
  - **条件超出分组维度或已有结果不含目标范围**，则重新搜索
- 使用`cat/grep`或者`python/bash`脚本获取`<handle>`内容会有结果丢失、内容转达错误的风险
- 脚本参数合法集合 **来自`references`下对应文档**，未读分册时禁止拼装命令行。如果执行返回`unrecognized arguments`，阅读 `references`下对应文档; **不要手工构建命令行参数** 或随意尝试参数。

### 搜索结果为空

- 搜索结果为空也是一种有效结果，请如实向用户汇报搜索结果为空。
- 禁止偷偷放宽用户隐含的条件（语义扩写，去掉搜索条件、去掉日期边界等）——那回答的是“另一个更宽的问题”，可能返回用户没要的文件                             
- 禁止任何形式的“因为 total 是 0 就降精度”    

### 精选/整理阶段获取全量数据中间过程失败或整体耗时长

- 用户搜索总数大时，需要持续拉取全部数据用来下游精选、去重、整理等，这个过程中需要及时向用户汇报进度
- 获取全量数据过程中遇到失败可以使用`--from <handle>`，该机制可以稳定禁止重搜，复用已有结果
